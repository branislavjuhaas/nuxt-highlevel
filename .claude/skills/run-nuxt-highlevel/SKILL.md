Nuxt 4 SPA (`ssr: false`) plus a Nitro API that analyzes a _target_ repo and
serves its graph at `/api/graph`. Shipped as a CLI (`bin/nuxt-highlevel.mjs`)
that boots the built `.output/` server. All paths are relative to the repo root,
and commands assume it as cwd.

The target repo comes from `NUXT_TARGET_ROOT` (empty = cwd, i.e. this repo
itself). Two fixtures exist: `test/fixtures/mono` (pnpm monorepo, has a cycle
and a rule violation) and `test/fixtures/standalone` (single app with local
layers/modules).

Pick the lightest mode: **API smoke** (curl the graph), **show** (headed Chrome
window for the user — default for "show me / open"), **inspect** (headless, only
when _you_ need a screenshot or DOM read), **CLI** (the built, shipped shape).
Show and inspect share one playwright-cli session and Chrome profile.

## Prerequisites

- **Node ≥ 24** (`engines`).
- **Vite+** — `vp` on PATH (`~/.vite-plus/bin`), which also provides
  `playwright-cli`. It drives the installed Google Chrome (`--browser=chrome`).

## Setup

```bash
vp install        # postinstall runs nuxt prepare
```

Fixture `.nuxt/` dirs are generated by vitest's global setup
(`test/prepare-fixture.ts`). If they're missing, `vp run test` once, or the
graph lacks auto-import edges and the UI warns.

## Before starting dev: check for a running one

Nuxt holds a per-project dev lock. A second `nuxt dev` exits with
`Another Nuxt dev server is already running (PID …)`. The user often has one
open already, and it may be pointed at a different target:

```bash
ss -ltnp 2>/dev/null | grep -E ':300[0-9] '
```

If one is running, **reuse it** (curl `/api/graph` to see which target it
serves) or ask before stopping it — it's usually the user's terminal session.
Never kill the port 3000 pid blindly.

## Run (agent path)

### Dev + API smoke

```bash
NUXT_TARGET_ROOT=$PWD/test/fixtures/mono \
  setsid bash -c 'vp run dev' > /tmp/nhl-dev.log 2>&1 < /dev/null &
disown

timeout 120 bash -c 'until curl -sf -o /dev/null http://localhost:3000/api/graph; do sleep 2; done' \
  && curl -s http://localhost:3000/api/graph \
     | node -e 'const g=JSON.parse(require("fs").readFileSync(0));console.log(g.nodes.length,"nodes",g.cycles.length,"cycles",g.warnings)' \
  || tail -20 /tmp/nhl-dev.log
```

`POST /api/refresh` re-runs the analysis (the result is cached). A non-OK
`/api/graph` carries the analyzer error in `message`.

### Browser session (show + inspect)

Every browser use goes through the app's own playwright-cli session
(`-s=nuxt-highlevel`) with real Chrome and a dedicated persistent profile, so
state (color mode, localStorage) survives between runs and never mixes with
other projects. Pass `-s` on _every_ command. A Chrome profile can't be open
twice, so never start plain `google-chrome` on this profile or `xdg-open`.

```bash
PW="playwright-cli -s=nuxt-highlevel"
PROFILE="$HOME/.cache/playwright-cli/profiles/nuxt-highlevel"
```

Shell variables don't carry over between Bash calls, so put these at the start
of each command that uses them.

**Show** (the user watches). After the smoke above succeeds, open once, then
stop — no repeated polling. If the page never loads, read `/tmp/nhl-dev.log`,
don't retry.

```bash
$PW open --headed --browser=chrome --profile="$PROFILE" http://localhost:3000/
```

Headed sessions never idle out. Leave the window open for the user. You can
still `eval`/`screenshot` in it to see what they see.

**Inspect** (only you look). Check `playwright-cli list` first. If the session is
already open (headed or not), reuse it with `goto` instead of `open`.
Otherwise, open headless:

```bash
$PW open --browser=chrome --profile="$PROFILE" http://localhost:3000/
$PW eval "document.querySelectorAll('.vue-flow__node').length"
$PW screenshot --filename=/tmp/nhl.png   # absolute path
$PW close                                # only for a headless session you opened
```

Wait a few seconds after `open`/`goto`. ELK layout runs client-side after the
graph loads. Running `open` again replaces the session (for example, headless →
headed). Reset the profile with `trash-put "$PROFILE"` (`delete-data` doesn't
reach a custom `--profile`).

Then `Read /tmp/nhl.png`. Drilling in is by double-click on a node, going up by
Backspace.

**Stop your own dev server** — kill the port's listener, not the `vp` parent
(`vp` → `@nuxt/cli` → `nuxt.mjs dev`, the grandchild holds the port). Only do
this for a server _you_ started:

```bash
kill "$(ss -ltnp 2>/dev/null | grep ':3000 ' | grep -oP 'pid=\K[0-9]+' | head -1)"
```

## Build + CLI (shipped shape)

```bash
vp run build                                          # nuxt build → .output/
node bin/nuxt-highlevel.mjs test/fixtures/mono --no-open
```

Prints a summary and the URL (`http://127.0.0.1:4777/`, next free port in
4777–4877), then keeps serving. Expected for mono:
`6 packages, 17 files, 1 cycles, 1 rule violations`. Flags: `--port`,
`--no-open`, `--prepare` (runs the target's own `nuxi prepare` where `.nuxt/`
is missing). Run it detached like dev and kill its port when done.

The globally installed `nuxt-highlevel` is a copy (`vp add -g "$PWD"`) — it
does **not** pick up a rebuild until reinstalled. Test with
`node bin/nuxt-highlevel.mjs`, not the global.

## Gotchas

- **Dev lock** — see "Before starting dev". Its error lands in the log, and your
  curl then hits the _other_ server, which may analyze a different target. Check
  the log's first lines before trusting results.
- **Do not run `vp build`** — raw Vite, no entry, fails. Always `vp run build`.
- **CLI needs `.output/`** — without it the bin exits with
  `Missing …/.output/server/index.mjs. Build first`.
- `warn: This project does not use vite-plus` from `vp run` is harmless.
- "N nuxt.config without .nuxt/" from the CLI on mono is expected — layers
  borrow the app's registry.
